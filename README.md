# SOLO Radar — Telegram / GitHub Actions

Бесплатный радар **кандидатов** на ранний PoW-майнинг, для GPU/SOLO-проектов на видеокартах NVIDIA и AMD — без привязки к конкретной модели. Работает по расписанию в GitHub Actions; домашний компьютер и VPS не нужны.

## Статус

- ✅ Подключение к Telegram подтверждено (приветственное сообщение).
- ✅ GitHub Actions запускается.
- ✅ Источники: GitHub, Bitcointalk при доступности, RSS 2Miners, новости pool-pay.com, публичные предпросмотры Telegram @miningrelease, @mining_note и @kryptex_channel_en.
- 🟡 Discord: поддержка добавлена в код, но **пока не подключена** — требуются разрешения Discord и секреты.
- ⚠️ Информация отбирается правилами по публичным описаниям. Это **не независимый аудит**, не прогноз дохода и не подтверждение mainnet.
- ⚠️ Bitcointalk может возвращать HTTPError из облака GitHub. Остальные источники продолжают проверяться.

В Settings → Secrets and variables → Actions:
- `TELEGRAM_BOT_TOKEN` — токен от @BotFather
- `TELEGRAM_CHAT_ID` — числовой ID личного чата

## Как подключить Discord

Discord не предоставляет чтение всех серверов по одной ссылке-приглашению. Требуется разрешённый доступ к конкретным каналам.

1. Создайте Discord Application на https://discord.com/developers/applications, затем Bot. Не используйте токен личной учётной записи Discord.
2. Если нужен текст сообщений, включите **Message Content Intent** в настройках Bot (с учётом требований Discord).
3. Пригласите бота на сервер, **если вы имеете право это делать**. Дайте только `View Channel` и `Read Message History` для соответствующего канала. Не нужны права администратора, отправки сообщений и управления сервером.
4. Включите режим разработчика Discord и скопируйте числовые идентификаторы интересующих каналов.
5. В **GitHub → Settings → Secrets and variables → Actions** добавьте:
   - `DISCORD_BOT_TOKEN` — секретный токен Discord-бота;
   - `DISCORD_CHANNEL_IDS` — числовые ID каналов через запятую.
6. Во вкладке Actions запустите `SOLO Radar — Telegram → Run workflow`. В логах должен появиться `Discord channel available`.

Если вы обычный участник стороннего Discord-сервера, пригласить своего бота без разрешения владельца обычно невозможно. Не обходите ограничения токеном обычного Discord-аккаунта (self-bot). Для публичных анонсов можно пользоваться открытыми сайтами и официальными RSS-лентами.

## Как работает отбор

Источники сканируются с расписанием 3, 13, 23, 33, 43 и 53 минуты каждого часа (фактическое время может задерживаться). Присылаются не более 3 новых GPU/PoW-кандидатов за запуск и без повторов. Статус каждого поля в сообщении отмечен как **не подтверждён**, пока нет внешней проверки.

**Пока не реализовано**: независимая проверка текущей сложности и хешрейта сети, автоматический расчёт шанса блока с подтверждёнными данными, доказательство торговой ликвидности, чтение Discord без разрешения.

Если при первом запуске нет подходящих проектов, уведомлений после приветствия не будет — это нормально.

## Проверить работу

GitHub → Actions → SOLO Radar — Telegram → нужный Run → scan → Check announcements and notify Telegram.

Если источники недоступны, лог покажет, какой именно. После настройки Discord проверяйте, что виден `Discord channel available`, а не `Discord channel unavailable`.

## Ограничения скорости и Telegram

Публичные каналы Telegram читаются только если доступна веб-страница `t.me/s/<channel>` с датированными сообщениями. При редиректе на страницу-превью без сообщений или при блокировке источник вернёт 0 кандидатов либо сообщение об ошибке. Это **не** подключение к Telegram API и не гарантия мгновенной доставки постов. GitHub Actions может задерживать или пропускать запуски. Наличие упоминания KawPow/Ethash и слова Mainnet не подтверждает фактический старт, сложность и доступность SOLO.

Проверка парсера выполняется в каждом workflow перед опросом источников. Падение тестов остановит рассылку и покажет ошибку в журнале. Для альтернативных публикаций предназначены дополнительные каналы, а не обход ограничений Discord.

## Этап GPU-анализа

Поддерживаются признаки AMD Radeon/OpenCL и NVIDIA CUDA, а также распространённые GPU-алгоритмы. Сигналы разделяются на **ранний запуск** (указано время UTC в окне от 24 часов после запуска до 72 часов перед запуском) и **GPU PoW-кандидат**. Дата, алгоритм, премайн и возможность SOLO пока извлекаются из текстов объявлений и требуют независимой проверки. Отсутствует достоверная проверка хешрейта и сложности блокчейнов; абсолютные шансы блока бот не выдумывает. Проверки запускаются автоматически после обновления кода.

## Этап SOLO Intelligence

В сообщениях появились **заявленные** награда за блок и интервал блока, если они прямо содержатся в тексте публикации, а также ссылки из текста на пул/обозреватель/исходники (когда доступны). Эти ссылки не проверены на безопасность, и отсутствие ссылки не доказывает отсутствие пула. Скрипт `solo_intel.py` содержит проверенную тестами математическую модель Пуассона `mine_probability(own_hashrate, network_hashrate, hours, block_seconds)`, но **она не используется для пользовательского прогноза**, пока нет актуальных проверенных хешрейтов в одинаковых единицах и подтверждённого среднего времени блока. Цена, доходность и ликвидность не выдумываются. Стадия раннего анонса не означает доказанного запуска mainnet.

## Режим Pool & Hold

SOLO **не обязателен**. SOLO Radar отдельно сообщает о молодых GPU PoW-сетях, где заявлены mainnet и обычный пул-майнинг (например, PPLNS/stratum), чтобы можно было рассмотреть добычу и накопление монет для возможной будущей продажи. Метка «🪙 Пул / накопление» означает только **кандидата**, а не рекомендацию удерживать актив: отсутствие premine, перспективы листинга, работа кошелька, доступность пула, эмиссия, ликвидность и финансовая выгода не подтверждены. Бот по-прежнему отправляет ранние анонсы и SOLO-кандидатов. Проверки намеренно не присваивают монетам прогнозы x10 или x100 без данных.

## Ссылки проекта в Telegram

Если первоисточник (например, публичный @miningrelease) предоставляет кнопки, SOLO Radar сохраняет и выводит отдельно **Discord**, **пул**, **кошелёк**, **майнер**, **обозреватель блоков** и **официальный сайт**. Ссылки отображаются в оповещении о новой монете, в `/start`, `/latest`, а также в историческом списке после нового сканирования. Система не придумывает ссылки и не обещает, что они безопасны, действительны или принадлежат разработчикам; проверяйте адрес и загрузки перед установкой. Для Discord не требуется подключать аккаунт пользователя ради отображения приглашения.

## Второй пользователь Telegram

Бот поддерживает несколько **разрешённых** личных чатов. Существующий `TELEGRAM_CHAT_ID` сохраняется без изменения. Новый человек открывает https://t.me/solo_radar_hunter_bot и нажимает `Start`; затем узнаёт свой **числовой** Telegram Chat ID (например, у @userinfobot) и передаёт его владельцу. Владелец добавляет в GitHub → Settings → Secrets and variables → Actions секрет `TELEGRAM_EXTRA_CHAT_IDS` со значением этого ID. Для нескольких новых людей вводят ID через запятую. Не нужно заменять исходный `TELEGRAM_CHAT_ID` и нельзя публиковать токен Telegram-бота. Новые пользователи получают те же уведомления и могут вызывать `/start`, `/latest`, `/status` и `/help` после ближайшего запуска Actions. Если человек не запускал диалог с ботом, Telegram не разрешит отправку сообщений. Неавторизованные ID игнорируются.

## Убрать задержки ответов /start: бесплатный Telegram webhook (Cloudflare Workers)

GitHub Actions может задерживать `schedule` на десятки минут; время ответов команд нельзя гарантировать при опросе `getUpdates` только через Actions. Поэтому создан отдельный `cloudflare-worker.mjs`: он отвечает на `/start`, `/latest`, `/status` и `/help` по webhook почти сразу. История монет берётся из **последнего** публичного `data/state.json` данного репозитория: скорость ответов и свежесть информации — разные вещи.

### Первоначальное подключение (однократно)

1. Создать бесплатный аккаунт на https://dash.cloudflare.com/ → **Workers & Pages** → **Create Worker** → открыть редактор Worker. Вставить **весь** код из файла `cloudflare-worker.mjs` и нажать Deploy. Полученный URL будет иметь вид `https://имя.workers.dev`.
2. В Cloudflare Worker → **Settings → Variables and Secrets** создать **секреты** (не обычные публичные переменные): `TELEGRAM_BOT_TOKEN` (существующий токен BotFather), `TELEGRAM_CHAT_ID` (цифровой ID владельца), `TELEGRAM_WEBHOOK_SECRET` (самостоятельно придуманная случайная строка из латинских букв/цифр, `_` и `-`, 24+ символа). Дополнительно `TELEGRAM_EXTRA_CHAT_IDS` (цифровые ID через запятую, если нужны). Никогда не вставлять секреты в исходный код.
3. В GitHub → **Settings → Secrets and variables → Actions** добавить ещё два репозиторных секрета: `TELEGRAM_WEBHOOK_URL` = полный `https://имя.workers.dev/webhook`, и `TELEGRAM_WEBHOOK_SECRET` = **точно та же** секретная строка из Cloudflare. Существующий `TELEGRAM_BOT_TOKEN` уже настроен, его не менять.
4. В GitHub → **Actions → Activate instant Telegram replies → Run workflow** выполнить регистрацию webhook с Telegram. В журнале должна появиться строка `Telegram webhook configured successfully`.
5. Проверить `https://имя.workers.dev/health` в браузере: ответ `SOLO Radar webhook online`. Написать `/status` в Telegram: ответ теперь приходит без ожидания следующего GitHub-сканирования.

После подключения GitHub Actions **автоматически перестаёт вызывать `getUpdates`**, если определён секрет `TELEGRAM_WEBHOOK_URL`; поиск монет и рассылка продолжаются по GitHub Actions. Webhook принимает только Telegram-события с правильным секретным заголовком и отвечает только на числовые Chat ID из списка разрешённых.

Важно: не активировать webhook до развёртывания Worker с нужными секретами. После активации бот отвечает из последнего сохранённого снимка — в нём могут быть старые анонсы, что будет явно видно по времени последней проверки. Работа Cloudflare Workers Free и GitHub Actions зависит от их доступности и лимитов.

## Кнопочное меню Telegram

Cloudflare Worker теперь отправляет компактное главное меню на `/start` и `/latest`: **Монеты на наблюдении**, **Последние находки**, **Статус**, **Справка**. Списки разбиты на страницы по четыре проекта; касание названия открывает карточку с кнопками **Анонс**, **Discord**, **Пул**, **Кошелёк**, **Майнер**, **Блоки**, **Сайт**, если в исходном сообщении были соответствующие HTTPS-адреса. Кнопки управления используют Telegram `callback_query` и редактируют текущее сообщение, чтобы не засорять чат. Webhook регистрируется с `allowed_updates = ["message", "callback_query"]`. Найденные ссылки **не являются проверенными**. Данные берутся из последнего снимка GitHub и могут устаревать, о чём сообщается в статусе.

## Сводка по каждой публикации — прямо в списке

В разделах **GitHub, Telegram, Bitcointalk, Пулы, RSS, Discord**, а также **Монеты на наблюдении** каждая запись теперь отображается с короткой текстовой сводкой ещё **до** открытия кнопки подробностей: дата публикации, заявленная дата mainnet (если исходный текст содержит дату с UTC), алгоритм, упоминания SOLO и пула. Для **GitHub** отдельно показывается дата **создания репозитория** из GitHub API; это не дата запуска монеты! Для других источников дата публикации отображается только если она получена из источника. Дата обнаружения радаром показывается отдельно в подробной карточке и не выдаётся за дату публикации. Если данных нет, бот пишет «дата не получена» / «не определён», не придумывая значения. Старые репозитории GitHub постепенно обновляются через публичный API, до трёх за сканирование. Проверка даты mainnet и фактической добычи по блокчейну пока отсутствует.

## Расширенное обнаружение и автоматический мониторинг (без OpenAI)

Радар ищет новые GPU PoW-проекты через **три независимых GitHub-поисковых запроса** (GPU mining/cryptocurrency, PoW mainnet, алгоритмы KawPow/Ethash/FishHash), объединяет результаты по идентификатору репозитория, не принимает форки и архивные проекты за новые запуски. GitHub-даты показывают создание репозитория, а не mainnet.

На каждом сканировании модуль `project_watch.py` автоматически **добавляет** кандидатов с достаточным количеством признаков в локальную базу `tracked_projects`, **перепроверяет** выбранные GitHub-репозитории на активность и **удаляет из списка наблюдения** неподходящие, устаревшие или архивированные. Записи истории остаются для аудита. Это **внутренние подписки радара**, не GitHub Watch/Star и не вступление в Telegram/Discord-группы от имени владельца. В боте есть кнопка **🎯 Активное отслеживание**. Новости пулов по-прежнему не выдаются за анонсы монет. GitHub Actions и данные публикуются бесплатно; расписание может задерживаться.

**OpenAI API выключен** в ежедневном workflow по желанию владельца. Суточные отчёты остаются в режиме «ПРАВИЛА (без ИИ)» и не требуют оплаты API. Внешний доступ к приватным группам и Discord-серверам не предоставлен. Не подтверждены цена, премайн, сеть и возможность продажи.

## Только GPU PoW-монеты (строгий фильтр)

Публичные источники могут содержать множество программ-майнеров, драйверов, мониторинговых сервисов и новостей пулов. Новый модуль `coin_filter.py` классифицирует записи как `coin_candidate`, `non_coin`, `unsupported_mining` или `insufficient`. Только `coin_candidate` могут появляться в сигналах, рекомендациях, суточном отчёте, меню источников и списке активного наблюдения. Фильтр исключает `good-miner`, `kobold-miner`, `crypto-connection-miner`, `NexusSwitch` и другие программы, сервисы, CPU-only, SHA-256/Scrypt ASIC-доминирующие монеты и PoS-токены. Неподтверждённые GPU-проекты с недостаточным текстом не объявляются добываемыми монетами. История сырого сканирования сохраняется для аудита, но не выводится как список монет.

**Важно:** `coin_candidate` — предварительный признак по тексту, **не** подтверждение живого mainnet, рабочего GPU-майнера, выплаты пула или возможности прибыльно продать добытые монеты. Фильтр может пропустить настоящую монету, если анонс недостаточно информативен. Источники не всегда доступны. Испытания включают известные ложные срабатывания и настоящие PoW-анонсы.

## Проверка возможности добычи (этап 20.11.2026)

Подключены два бесплатных внешних источника: **Mining Scan** (`https://mining-scan.com/data-api`, раз в 6 часов) и **BackPoW** (`https://backpow.com/api`, проверка подходящих известных монет раз в сутки). Никаких API-ключей и подписок не требуется. Mining Scan сообщает сведения о пулах, блоках и других сетевых признаках; BackPoW — сложность, сеть и высоту блока при точном соответствии каноническому имени из каталога. При несовпадении или отсутствии данных поля остаются неизвестными.

Каждая монета получает уровень: **только анонс**, **пулы есть в каталоге**, **есть сообщения об активности сети**. Данные должны быть свежими; старые показатели не считаются актуальным доказательством. Даже последний уровень **не подтверждает, что RTX 5070 Ti может майнить**, что существуют рабочие Stratum-адреса, выплаты или ликвидная биржа. Код оценки: `mineability.py`; данные прикрепляются к `data/state.json` и выводятся в подробных карточках Telegram. Модуль `test_mineability.py` тестирует пороги, устаревшие данные и запрет ложных утверждений.
