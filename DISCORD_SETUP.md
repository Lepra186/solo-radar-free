# Discord для SOLO Radar — настройка в режиме только чтения

Код Discord уже установлен: `discord_sources.py`. GitHub Actions считывает только те каналы, куда бот был приглашён с разрешения администратора. Никаких пользовательских токенов, self-bot, массовой подписки или обхода закрытых каналов.

## Настройка на стороне Discord

1. Зайди на https://discord.com/developers/applications и нажми **New Application** — назови её **SOLO Radar Watcher**.
2. Открой вкладку **Bot**. Создай (или открой) бота и включи **Message Content Intent**. В Discord это привилегированное разрешение, но для небольшого приложения его обычно можно включить прямо в Developer Portal.
3. Скопируй **Bot Token**, никому его не отправляй в чат и не размещай в README или исходниках.
4. Открой **Installation / OAuth2 → URL Generator**, выбери `bot`, разрешения **View Channels** и **Read Message History**. Боту **не нужны** Administrator, Send Messages, Manage Roles или управление участниками.
5. Пригласи бота **только на сервер, где у тебя есть право добавить бота**. На чужих серверах добавление должен разрешить администратор.
6. В настройках Discord включи **Developer Mode**, затем **Copy Channel ID** у текстовых каналов с анонсами PoW/mainnet. Подойдут каналы announcements, launches, coin-announcements; имена каналов не влияют на работу — нужны числовые ID.

## Подключение к GitHub

Открой: https://github.com/Lepra186/solo-radar-free/settings/secrets/actions

Добавь secrets:

- `DISCORD_BOT_TOKEN` — токен созданного Discord-бота.
- `DISCORD_CHANNEL_IDS` — ID разрешённых каналов через запятую, максимум 8 (пример: `123456789012345678,234567890123456789`).

После этого GitHub Actions подхватит настройки при следующем скане. Можно вручную запустить workflow **SOLO Radar — Telegram**, но обычно это не нужно.

## Проверка

В логах GitHub Actions искать:
- `Discord discovery status: active authorized channels: N posts: M` — канал доступен.
- `not_configured` — токен и/или ID ещё не добавлены.
- `unavailable` — проверь разрешения, Message Content Intent, правильность ID и права в конкретном канале.

Полученные сообщения фильтруются по дате (до 96 часов) и `coin_filter.py`. Сервисные новости, майнеры и токены не считаются отдельными GPU PoW-монетами.

## Другие источники

- GitHub — новые исходники проектов, проверка активности репозиториев.
- Telegram и Bitcointalk — анонсы, но не доказательство запуска.
- Mining Scan — открытый API `https://mining-scan.com/api/export/coins`: проверка упоминаний пулов и блоков, без превращения каталога в список новых монет. Кеш на 6 часов. Учитывается актуальность данных.
- RSS и сайты пулов — дополнительные сигналы для последующей проверки. 

Потенциально полезные дальнейшие источники: WhatToMine (документирован API каталога монет, https://www.whattomine.com/api-docs), собственные API майнинг-пулов и обозреватели блоков. Перед включением каждого требуется проверить лицензию, доступность, лимиты и наличие достоверных данных.
